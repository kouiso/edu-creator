# 👶 Beginner Review Skill

## 目的

**完全な初心者の視点**でチュートリアルをレビューし、挫折ポイントを事前に排除する。

## 核心原則

### 1. 初心者は「知らない」が前提

- 「これくらい知ってるだろう」という思い込みを排除
- 全ての前提知識を明示する
- 「当然」「簡単」という言葉は使わない

### 2. 初心者は「失敗する」が前提

- エラーは「起こり得る」ではなく「必ず起こる」
- エラーメッセージの意味が分からないことを想定
- 「うまくいかない時」の対処法を必ず記載

### 3. 初心者は「質問できない」が前提

- チュートリアル内で完結する情報提供
- 「ググってください」は禁止
- よくある疑問を先回りして解説

## レビュー観点

### 1. 専門用語チェック

#### 評価項目
- [ ] 初出の専門用語に注釈があるか？
- [ ] 注釈は初心者が理解できる言葉か？
- [ ] 略語は正式名称も併記されているか？

#### NG例

```markdown
❌ 「Next.jsはSSRに対応しています」
→ SSRが何か分からない
```

#### OK例

```markdown
✅ 「Next.jsはSSR（Server Side Rendering：サーバー側でHTMLを生成する仕組み）に対応しています」
→ 略語の正式名称と意味が併記されている
```

### 2. 段階性チェック

#### 評価項目
- [ ] いきなり複雑なコードが出てこないか？
- [ ] 一つ一つ段階的に学べるか？
- [ ] 前のセクションの知識を前提にしているか明示されているか？

#### NG例

```typescript
❌ いきなり登場
const [data, setData] = useState([]);
useEffect(() => { fetchData(); }, []);
const memoizedValue = useMemo(() => data.filter(x => x.active), [data]);
```

#### OK例

```typescript
✅ 段階的に導入

// Step 1: まずuseStateだけ
const [count, setCount] = useState(0);

// Step 2: 次にuseEffect
useEffect(() => { console.log(count); }, [count]);

// Step 3: 後からuseMemo（必要になってから）
const doubledCount = useMemo(() => count * 2, [count]);
```

### 3. エラー対処チェック

#### 評価項目
- [ ] よくあるエラーが列挙されているか？
- [ ] エラーメッセージの読み方が説明されているか？
- [ ] 解決策が具体的か？

#### NG例

```markdown
❌ 「エラーが出たら、ログを確認してください」
→ どこでログを見るか分からない
```

#### OK例

```markdown
✅ 「エラーが出た場合の対処法」

### エラー1: `Module not found`

**このエラーが出る場所**: ターミナル画面

**原因**: 必要なパッケージがインストールされていません。

**解決策**:
1. ターミナルで以下のコマンドを実行
   ```bash
   npm install
   ```
2. インストール完了後、再度実行
   ```bash
   npm run dev
   ```
```

### 4. 前提知識チェック

#### 評価項目
- [ ] 必要な前提知識が明示されているか？
- [ ] 前提知識がない人への補足があるか？
- [ ] 「知っていて当然」の態度がないか？

#### NG例

```markdown
❌ 「Gitでクローンしてください」
→ Gitを知らない人には不親切
```

#### OK例

```markdown
✅ 「Gitでクローンしてください」

> 💡 **Gitが初めての方へ**
> Gitは、コードのバージョン管理をするツールです。
> まだインストールしていない場合は、[こちらのガイド](...)を参照してインストールしてください。
```

### 5. 「なぜ」チェック

#### 評価項目
- [ ] コードの「なぜ」が説明されているか？
- [ ] 「何をするか」だけでなく「なぜそうするか」が分かるか？
- [ ] 初心者が「理解」ではなく「暗記」にならないか？

#### NG例

```typescript
❌ 「この関数を使います」
export default function Home() {
  return <div>Hello</div>;
}
```

#### OK例

```typescript
✅ 「なぜこの書き方をするのか」

// Next.jsでは、ページごとにファイルを作成します。
// このファイルがホームページ（トップページ）になります。
export default function Home() {
  // return の後に書いたものが、画面に表示されます
  return <div>Hello</div>;
}
```

## レビュー判定基準

### ✅ 合格基準

以下の**全て**を満たす必要があります：

1. 専門用語に注釈がある
2. 段階的に学べる構成
3. よくあるエラーと対処法が記載
4. 前提知識が明示されている
5. 「なぜ」が説明されている

### ⚠️ 修正が必要

以下の**いずれか**に該当する場合：

1. 専門用語が注釈なしで3つ以上登場
2. いきなり複雑なコード（10行以上）が登場
3. エラー対処法がない
4. 前提知識が不明
5. 「なぜ」の説明が半分以下

## 実例: 良い vs 悪い

### 悪い例（初心者視点欠如）

```markdown
Next.jsでAPIルートを作成します。以下のコードを追加してください。

\```typescript
export default async function handler(req, res) {
  const data = await prisma.user.findMany();
  res.json(data);
}
\```
```

**問題点**
- APIルートが何か分からない
- prismaが何か分からない
- async/awaitが何か分からない
- エラー対処法がない

### 良い例（初心者視点あり）

```markdown
## APIルート（データを取得する仕組み）を作成する

### このセクションで学ぶこと
- APIルートとは何か
- データベースからデータを取得する方法

### なぜAPIルートが必要か
フロントエンド（画面）からデータベースに直接アクセスすると、
セキュリティリスクがあります。
APIルートを経由することで、安全にデータを取得できます。

### コード例

\```typescript
// pages/api/users.ts
// このファイルがAPIルート（データを取得するための窓口）になります

export default async function handler(req, res) {
  // async/await: データベースからの応答を待つための書き方
  
  // prisma: データベースにアクセスするためのツール
  // user.findMany(): 全てのユーザーを取得
  const data = await prisma.user.findMany();
  
  // res.json(data): 取得したデータをJSON形式で返す
  res.json(data);
}
\```

### よくあるエラー

#### エラー1: `prisma is not defined`
**原因**: Prismaがインストールされていません。
**解決策**: ターミナルで `npm install @prisma/client` を実行してください。

#### エラー2: `Cannot connect to database`
**原因**: データベースが起動していません。
**解決策**: Dockerでデータベースを起動してください（`docker-compose up -d`）。
```
