# ✅ Quality Check Skill

## 目的

チュートリアルの品質を客観的に評価し、初心者が安心して学習できるレベルに達していることを保証する。

## 評価観点（LLM Judge基準）

### 1. 正確性 (Accuracy) - 重み: 30%

#### 評価項目
- [ ] コードは実際に動作するか？
- [ ] 最新のAPIやベストプラクティスに準拠しているか？
- [ ] 非推奨（deprecated）なAPIを使用していないか？
- [ ] 技術的に正確な説明がされているか？

#### 評価基準

| スコア | 基準 |
|--------|------|
| 5 | 全てのコードが動作し、最新のベストプラクティスに完全準拠 |
| 4 | ほぼ全てのコードが動作し、小さな改善余地がある程度 |
| 3 | 一部のコードに問題があるが、修正は容易 |
| 2 | 複数のコードに問題があり、修正に時間がかかる |
| 1 | コードがほとんど動作しない、または重大なエラーがある |

### 2. 安全性 (Safety) - 重み: 25%

#### 評価項目
- [ ] XSS/SQLインジェクション対策がされているか？
- [ ] 入力値のバリデーションがあるか？
- [ ] エラーハンドリングが適切か？
- [ ] 機密情報がハードコードされていないか？

#### 評価基準

| スコア | 基準 |
|--------|------|
| 5 | セキュリティ対策が完璧、エラーハンドリングも十分 |
| 4 | 主要な対策はあるが、一部改善余地あり |
| 3 | 基本的な対策はあるが、不十分な箇所が複数 |
| 2 | セキュリティリスクがあり、エラーハンドリングも不足 |
| 1 | 重大なセキュリティリスクがある |

### 3. 初心者理解度 (Learnability) - 重み: 30%

#### 評価項目
- [ ] 段階的に理解できる構成か？
- [ ] 専門用語に注釈がついているか？
- [ ] 「なぜ」が説明されているか？
- [ ] 初心者が挫折しない難易度か？

#### 評価基準

| スコア | 基準 |
|--------|------|
| 5 | 初心者が完全に理解できる、段階的で丁寧な説明 |
| 4 | ほぼ理解できるが、一部説明不足な箇所あり |
| 3 | 理解できる部分とできない部分が混在 |
| 2 | 専門的すぎて、初心者には難しい |
| 1 | 初心者には全く理解できない |

### 4. コード品質 (Code Quality) - 重み: 15%

#### 評価項目
- [ ] 変数名・関数名が適切か？
- [ ] コードに適切なコメントがあるか？
- [ ] 重複コードがないか？
- [ ] 適切な抽象化レベルか？

#### 評価基準

| スコア | 基準 |
|--------|------|
| 5 | プロダクションレベルのコード品質 |
| 4 | 良好な品質だが、小さな改善余地あり |
| 3 | 動作するが、リファクタリングが望ましい |
| 2 | 品質に問題があり、改善が必要 |
| 1 | 保守不可能なコード |

## 総合評価（LLM Judge）

### スコア計算式

```
総合スコア = (正確性 × 0.30) + (安全性 × 0.25) + (初心者理解度 × 0.30) + (コード品質 × 0.15)
```

### 合格基準

| 総合スコア | 判定 | アクション |
|-----------|------|-----------|
| 4.5 - 5.0 | ✅ Excellent | そのまま公開可能 |
| 4.0 - 4.4 | ✅ Good | 軽微な修正後に公開 |
| 3.5 - 3.9 | ⚠️ Fair | 複数箇所の修正が必要 |
| 3.0 - 3.4 | ⚠️ Poor | 大幅な修正が必要 |
| < 3.0 | ❌ Reject | 再作成を推奨 |

## 品質チェックプロセス

### 1. 自動チェック

```python
# 構文エラーチェック
check_syntax_errors(code_blocks)

# 非推奨APIチェック
check_deprecated_apis(code_blocks)

# セキュリティチェック
check_security_issues(code_blocks)
```

### 2. 手動レビュー

- ContentPM: 正確性・コード品質
- QualityPM: 安全性・初心者理解度
- BeginnerAdvocate: 初心者視点での難易度

### 3. LLM Judge評価

```python
from utils.llm_judge import evaluate_tutorial

result = evaluate_tutorial(
    tutorial=tutorial_data,
    criteria=["accuracy", "safety", "learnability", "code_quality"],
    weights=[0.30, 0.25, 0.30, 0.15],
)

print(f"総合スコア: {result.total_score}")
print(f"判定: {result.verdict}")
```

## レビュー指摘テンプレート

### Critical（スコア1-2の場合）

```markdown
## ⚠️ Critical Issues

### 正確性
- **問題**: [具体的な問題]
- **スコア**: 2/5
- **理由**: [なぜこのスコアか]
- **修正案**: [具体的な修正方法]

### 安全性
- **問題**: [具体的な問題]
- **スコア**: 1/5
- **理由**: [なぜこのスコアか]
- **修正案**: [具体的な修正方法]
```

### Fair（スコア3の場合）

```markdown
## 📝 Improvement Needed

### 初心者理解度
- **現状**: 専門用語が多く、注釈が不足
- **スコア**: 3/5
- **改善案**: 各専門用語に（）で注釈を追加
```

### Good/Excellent（スコア4-5の場合）

```markdown
## ✅ Quality Approved

### 総合評価
- **スコア**: 4.5/5
- **判定**: Excellent
- **良かった点**:
  - コードが正確で動作する
  - セキュリティ対策が十分
  - 初心者でも理解しやすい

### 軽微な改善提案
- [あれば記載]
```

## チェックリスト

品質チェック時の確認項目：

- [ ] 総合スコアが4.0以上か？
- [ ] Critical（スコア1-2）の項目がないか？
- [ ] 全てのコードブロックが動作確認済みか？
- [ ] セキュリティリスクがないか？
- [ ] 初心者が理解できる難易度か？
- [ ] エラーハンドリングが含まれているか？
