# 📝 Tutorial Writing Skill

## 目的

初心者エンジニアが挫折せず、自信を持って学習を進められるチュートリアルを作成する。

## 核心原則

### 1. 初心者の心理状態を理解する

- 初心者は「自分は理解できない」という不安を常に抱えている
- 専門用語は「知っていて当然」ではなく「初めて聞く言葉」
- エラーが出ると「自分のせい」と思い込み、挫折しやすい

### 2. 段階的な理解を促す

- 一度に多くの概念を詰め込まない
- 各セクションで学ぶことは1〜2つに絞る
- 前のセクションの知識を前提とする（積み上げ式）

### 3. 実感できる成功体験を提供

- 「動いた！」という体験を早い段階で提供
- 結果が目に見える形で確認できる
- 小さな達成を積み重ねる

## ベストプラクティス

### ✅ やるべきこと

1. **必ず「なぜ」を説明する**
   - ❌ 「この関数を使います」
   - ✅ 「データを保存するために、この関数を使います。これにより、ページをリロードしても情報が消えなくなります」

2. **専門用語には必ず注釈をつける**
   - ❌ 「コンポーネントを作成します」
   - ✅ 「コンポーネント（画面を構成する部品）を作成します」

3. **コード例には必ずコメントをつける**
   ```typescript
   // ❌ コメントなし
   const [count, setCount] = useState(0);
   
   // ✅ コメントあり
   // count: 現在のカウント数を保存する変数
   // setCount: カウント数を更新するための関数
   const [count, setCount] = useState(0);
   ```

4. **エラーハンドリングを必ず含める**
   - 「エラーが出た時の対処法」を先に示す
   - よくあるエラーとその解決策を列挙

5. **図解・例え話を活用**
   - 抽象的な概念は、身近な例え（お弁当箱、本棚など）で説明
   - スクリーンショットで視覚的に補足

### ❌ 絶対禁止事項

1. **初心者を萎縮させる表現**
   - ❌ 「簡単です」「すぐできます」「当然ですが」
   - ❌ 「基本的なことなので説明は省略します」

2. **コードの意味を説明せずコピペを促す**
   - ❌ 「以下のコードをコピペしてください」
   - ✅ 「以下のコードは〇〇を実現するものです。1行ずつ見ていきましょう」

3. **エラーハンドリングのないコード例**
   - 必ずtry-catchやエラーチェックを含める
   - 「エラーが出ない前提」のコードは書かない

4. **専門用語の説明なしでの使用**
   - 初出の専門用語は必ず注釈または説明を追加

5. **「ググってください」系の指示**
   - ❌ 「詳しくは公式ドキュメントを参照してください」
   - ✅ 「詳細は公式ドキュメント（https://...）の第2章で解説されています」

## 文章構成テンプレート

### セクション開始時

```markdown
## [セクションタイトル]

### このセクションで学ぶこと
- ポイント1
- ポイント2

### なぜこれを学ぶのか
[実際の開発でどう役立つかを説明]
```

### コード例の提示

```markdown
### コード例

以下のコードは、[実現したいこと]を行います。

\```typescript
// [1行目の説明]
const example = "hello";

// [2行目の説明]
console.log(example);
\```

#### コードの詳細解説
1. 1行目: [詳しい説明]
2. 2行目: [詳しい説明]
```

### エラー対処の記載

```markdown
### よくあるエラーと対処法

#### エラー1: [エラーメッセージ]
**原因**: [なぜこのエラーが出るか]
**解決策**: [具体的な修正方法]

#### エラー2: [エラーメッセージ]
...
```

## チェックリスト

チュートリアルを執筆したら、以下を確認してください：

- [ ] 各セクションで学ぶことが明確か？
- [ ] 専門用語に注釈がついているか？
- [ ] コード例にコメントがついているか？
- [ ] エラーハンドリングが含まれているか？
- [ ] 「なぜ」が説明されているか？
- [ ] 初心者を萎縮させる表現がないか？
- [ ] 実際に手を動かせる内容か？
- [ ] 成功体験が得られる構成か？

## 参考: 良い例 vs 悪い例

### 変数の説明

**❌ 悪い例**
```
変数を定義します。
const userName = "Taro";
```

**✅ 良い例**
```
変数（データを入れる箱）を定義します。
ここでは、ユーザーの名前を保存するために `userName` という名前の箱を用意し、
その中に「Taro」という名前を入れています。

const userName = "Taro";  // userName という箱に "Taro" を保存
```

### 関数の説明

**❌ 悪い例**
```
関数を作成します。
function greet() {
  console.log("Hello");
}
```

**✅ 良い例**
```
関数（処理をまとめた箱）を作成します。
ここでは、挨拶を表示する処理を `greet` という名前でまとめています。
こうすることで、何度でも同じ挨拶を簡単に表示できるようになります。

function greet() {
  console.log("Hello");  // 画面に「Hello」と表示
}

// 使い方
greet();  // → 画面に「Hello」と表示されます
```
